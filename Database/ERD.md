# ERD 기초와 설계 순서

## 들어가기전

한달동안 기획 및 개발을 하는 해커톤에 참여해보며 백엔드, 프론트엔드 팀원들과 원활하게 만들어주는 ERD를 작성할 기회가 생기면서 배운 내용을 정리하고자 한다.

## 1. 기본 개념

### ERD (Entity Relationship Diagram)

- 정의: 데이터베이스의 테이블과 컬럼, 테이블 사이의 관계를 나타낸 그림입니다.
- 사용하는 이유: 개발 전에 데이터를 어디에 저장할지 정하고, 팀원들과 같은 구조를 보며 이야기할 수 있습니다.

### 기본 용어

| 용어           | 의미                                         | 직접 작성한 예시               |
| -------------- | -------------------------------------------- | ------------------------------ |
| Entity / Table | 저장할 데이터의 종류                         | `users`, `orders`              |
| Row / Record   | 테이블에 저장된 한 건의 데이터               | 사용자 한 명의 정보            |
| Column / Field | 데이터가 가진 속성                           | `name`, `email`                |
| PK             | 각 데이터를 고유하게 구분하는 키             | `users.id`                     |
| FK             | 다른 테이블의 PK를 참조하는 키               | `orders.user_id`               |
| NULL           | 값이 없음을 나타내는 상태                    | 배송 메모를 작성하지 않은 경우 |
| NOT NULL       | 반드시 값이 있어야 한다는 제약조건           | 주문 생성 시 `user_id` 필수    |
| UNIQUE         | 같은 값을 중복해서 저장할 수 없다는 제약조건 | 사용자 `email`                 |

## 2. 테이블 관계

### 1:1 (One to One)

- 의미: 한쪽 데이터 하나가 다른 쪽 데이터 하나와 연결되는 관계입니다.
- 사용 예시: 사용자 한 명이 프로필 하나를 가지는 `users`와 `user_profiles` 관계입니다.

### 1:N (One to Many)

- 의미: 한쪽 데이터 하나가 다른 쪽 데이터 여러 개와 연결되는 관계입니다.
- 사용 예시: 사용자 한 명이 여러 주문을 만들 수 있는 `users`와 `orders` 관계입니다.

### N:M (Many to Many)

- 의미: 양쪽 데이터가 서로 여러 개씩 연결되는 관계입니다.
- 중간 테이블이 필요한 이유: 관계형 데이터베이스에서 N:M 관계를 바로 저장하기 어렵기 때문에 두 개의 1:N 관계로 나누기 위해 사용합니다.
- 사용 예시: 주문 하나에 여러 상품이 들어가고, 상품 하나도 여러 주문에 포함될 수 있습니다. `order_items`가 `orders`와 `products`를 연결합니다.

## 3. 관계 읽는 방법

```text
orders.user_id -> users.id
```

- `orders.user_id`의 역할: 주문을 생성한 사용자를 가리키는 FK입니다.
- `users.id`의 역할: 사용자를 고유하게 구분하는 PK입니다.
- 두 테이블의 관계: 사용자 한 명이 여러 주문을 가질 수 있으므로 1:N 관계입니다.

## 4. ERD 설계 순서

1. 사용자 흐름과 핵심 기능을 확인한다.
2. 저장해야 할 데이터를 문장으로 나열한다.
3. 같은 성격의 데이터를 테이블로 묶는다.
4. 각 테이블의 PK를 정한다.
5. 테이블 사이의 관계와 FK를 정한다.
6. 필수값, 중복 허용 여부 등의 제약조건을 정한다.
7. 샘플 데이터를 넣어 조회와 수정이 가능한지 확인한다.

## 5. 직접 설계해보기

- 서비스 또는 기능: 사용자가 상품을 골라 주문하는 기능
- 필요한 테이블: `users`, `orders`, `products`, `order_items`
- 각 테이블의 역할:
  - `users`: 사용자 정보를 저장합니다.
  - `orders`: 주문 날짜와 주문 상태를 저장합니다.
  - `products`: 상품명과 가격을 저장합니다.
  - `order_items`: 한 주문에 담긴 상품, 수량, 주문 당시 가격을 저장합니다.
- 테이블 사이의 관계:
  - `users` 1:N `orders`
  - `orders` 1:N `order_items`
  - `products` 1:N `order_items`
  - 결과적으로 `orders`와 `products`는 `order_items`를 통한 N:M 관계입니다.
- 더 생각해 볼 부분: 주문을 취소했을 때 데이터를 지울지, 주문 상태만 바꿀지 정해야 합니다.
