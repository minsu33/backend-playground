# 백엔드 개발자가 하는 일

백엔드 개발자는 화면 뒤에서 사용자의 요청을 처리합니다. 서버와 데이터베이스를 만들고 외부 서비스를 연결하면서, 서비스의 규칙과 데이터를 안전하게 관리합니다.

## 1. 프론트엔드와 백엔드

| 구분 | 주요 역할 |
| --- | --- |
| 프론트엔드 | 사용자가 보는 화면과 상호작용을 구현한다. |
| 백엔드 | 요청을 처리하고 비즈니스 로직을 실행하며 데이터를 저장한다. |

예를 들어 사용자가 `오늘의 기록 저장` 버튼을 누르면 프론트엔드는 입력값을 서버에 전달합니다. 백엔드는 로그인한 사용자인지 확인하고, 입력값을 검사한 뒤 데이터베이스에 기록을 저장하고 결과를 응답합니다.

## 2. 요청이 처리되는 기본 흐름

```text
사용자 행동
    ↓
프론트엔드의 API 요청
    ↓
Controller: 요청을 받음
    ↓
Service: 서비스 규칙을 처리함
    ↓
Repository: 데이터베이스에 접근함
    ↓
Database: 데이터를 조회하거나 저장함
    ↓
API 응답
    ↓
프론트엔드가 결과를 화면에 표시
```

### 계층별 역할

| 계층 | 역할 |
| --- | --- |
| Controller | 요청 URL, HTTP Method, 입력값을 받아 Service에 전달한다. |
| Service | 계산, 상태 변경, 권한 확인 등 서비스의 핵심 규칙을 처리한다. |
| Repository | 데이터베이스 조회와 저장을 담당한다. |
| Database | 사용자, 게시글, 주문과 같은 데이터를 보관한다. |

계층 이름과 세부 역할은 프로젝트마다 조금씩 다를 수 있습니다.

## 3. 프로젝트에서 맡는 일

### 요구사항 확인

- 사용자가 어떤 기능을 사용하는지 확인한다.
- 화면마다 조회하거나 저장해야 할 데이터를 찾는다.
- 정상 상황뿐 아니라 빈 데이터와 실패 상황도 확인한다.

### 데이터 설계

- 서비스에 필요한 도메인과 용어를 정리한다.
- 테이블, 컬럼, PK와 FK를 정한다.
- 데이터 관계와 제약조건을 ERD로 표현한다.

### API 설계

- 프론트엔드와 주고받을 요청과 응답을 정한다.
- HTTP Method와 Endpoint를 정한다.
- 인증, 권한, 상태 코드와 오류 응답을 정한다.

### 기능 구현

- 비즈니스 로직을 코드로 구현한다.
- 데이터베이스 조회와 저장 기능을 구현한다.
- 소셜 로그인, 파일 저장소, 외부 API 등을 연동한다.
- 잘못된 요청이나 서버 오류를 처리한다.

### 테스트와 협업

- API가 명세대로 동작하는지 테스트한다.
- 프론트엔드와 요청·응답 형식을 맞춘다.
- API나 데이터 구조가 바뀌면 팀에 공유하고 문서를 수정한다.
- 코드 리뷰를 통해 오류와 개선점을 확인한다.

### 배포와 운영

- 서버와 데이터베이스를 배포 환경에 구성한다.
- 비밀번호와 API 키를 환경변수로 관리한다.
- 로그와 모니터링을 통해 오류 원인을 확인한다.
- 데이터 백업, 성능, 보안을 점검한다.

## 4. 알아야 하는 주요 개념

| 분야 | 주요 개념 | 필요한 이유 |
| --- | --- | --- |
| 프로그래밍 | Java, 객체지향, 예외 처리 | 서버 로직을 구현하기 위해 필요하다. |
| 웹 | HTTP, REST API, JSON | 클라이언트와 요청·응답을 주고받기 위해 필요하다. |
| Spring | Controller, Service, Repository, DI | 서버 애플리케이션의 구조를 만들기 위해 필요하다. |
| 데이터베이스 | SQL, ERD, PK/FK, 정규화 | 데이터를 올바르게 저장하고 조회하기 위해 필요하다. |
| 데이터 처리 | 트랜잭션, 동시성 | 여러 데이터 변경을 안전하게 처리하기 위해 필요하다. |
| 인증과 보안 | 세션, JWT, OAuth, 권한 | 사용자와 데이터를 보호하기 위해 필요하다. |
| 테스트 | 단위 테스트, 통합 테스트, API 테스트 | 기능이 의도대로 동작하는지 확인하기 위해 필요하다. |
| 협업 | Git, 브랜치, PR, API 명세 | 팀원이 같은 기준으로 개발하기 위해 필요하다. |
| 배포 | Linux, Docker, 환경변수, CI/CD | 만든 서버를 실제 환경에서 실행하기 위해 필요하다. |

이 개념들을 전부 익힌 다음에야 프로젝트를 시작할 수 있는 건 아닙니다. 작은 기능부터 만들어 보고, 막히는 부분을 공부하며 하나씩 연결해 가면 됩니다.

## 5. 백엔드가 만드는 결과물

- ERD와 테이블 정의
- API 목록과 상세 명세
- 서버 애플리케이션 코드
- 데이터베이스 스키마와 초기 데이터
- 테스트 코드와 API 테스트 결과
- 환경변수 및 실행 설정
- 배포 방법과 오류 대응 기록

## 6. 코딩 외에 중요한 역할

백엔드 개발은 API 코드만 작성한다고 끝나지 않습니다.

- 기획, UI, ERD, API가 같은 의미를 사용하는지 확인한다.
- 기능이 실패했을 때 어떤 응답을 보낼지 정한다.
- 데이터가 잘못 저장되거나 중복되지 않도록 규칙을 만든다.
- 구현 범위와 기술적 한계를 팀원에게 설명한다.
- 제한된 일정에서는 핵심 기능과 나중에 구현할 기능을 구분한다.

결국 화면에 필요한 데이터를 안정적으로 보내고, 서비스 규칙이 바뀌었을 때 어디를 고쳐야 할지 쉽게 찾을 수 있도록 만드는 것이 중요합니다.
